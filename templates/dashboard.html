PROJECT ARGUS MANIFESTO

Alert Response & Guardian Unified System (ARGUS) is an enterprise-grade cloud incident monitoring and telemetry platform. Designed as the real-time operational counterpart to the NEXUS Autonomous Cyber Warfare Simulation, ARGUS provides persistent host telemetry collection, automated anomaly alerting, and cloud storage integration for security operations teams.

Context & Motivation: In modern cloud-native architectures, fragmented log management causes critical detection blindspots. ARGUS bridges host-level systemd telemetry with AWS cloud services (EC2, S3, IAM, CloudWatch) behind an Nginx reverse proxy, providing a continuous open-to-resolved incident lifecycle with verifiable zero-secret authentication.

System Architecture

24/7 Systemd Daemon (Host Telemetry)

A continuous Python background daemon running as an active Linux service (monitor.service) polls root storage pools, virtual memory, normalized load average, and journalctl authentication logs every 60 seconds. Anomalies and threshold breaches are instantly dispatched into the alert pipeline.

Cloud Storage Data Lake (AWS S3 & IAM)

Every ingested incident payload is transformed into an immutable JSON log and committed to an Amazon S3 bucket (argus-alerts-vamsi-2026). Authentication is handled via an AWS IAM Instance Profile (ArgusEC2S3Role), enforcing the principle of least privilege with zero hardcoded API keys.

Reverse Proxy & Web Security (Nginx + SSL)

Incoming web traffic is routed through Nginx reverse proxy terminating TLS with Let's Encrypt certificates. Nginx enforces security headers (HSTS, X-Frame-Options, nosniff) and forwards internal requests to the containerized Gunicorn WSGI server on port 5000.

Infrastructure as Code & CI/CD

The entire cloud footprint is codified using Terraform (main.tf) for 100% reproducible deployments. Code changes pushed to GitHub automatically trigger a GitHub Actions workflow that executes the Pytest test matrix and initiates zero-downtime EC2 deployment over SSH.

Incident Lifecycle Flow

  1. Telemetry Ingestion: monitor.service collects hardware and authentication metrics on a continuous 60s cron interval.
  2. Breach Evaluation: System load and capacity are compared against operational thresholds; security anomalies in sshd trigger instant priority events.
  3. Cloud Persistence: Incidents are posted to the REST API, mirrored into Amazon S3, and published to CloudWatch custom metrics.
  4. Operator War Room: Incidents appear live on the console with automatic real-time synchronization.
  5. Lifecycle Resolution: Operators transition alerts from Open → Acknowledged → Resolved via UI buttons or the resolve_alert.py CLI, permanently updating the cloud S3 state.
